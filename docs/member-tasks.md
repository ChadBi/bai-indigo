## 2. 队员 1：染艺寻踪

任务入口：[CultureModule.vue](../app/src/modules/culture/CultureModule.vue)。详细模块约定：[culture/README.md](../app/src/modules/culture/README.md)。

### 已经提供

- CultureEntry 和 SourceRef 类型。
- 一条核对来源的文化资料样例；当前没有文化实物图片。
- 公共卡片、按钮、详情弹窗、来源列表、图片组件和空状态。
- 最小列表和详情，已接入正式路由。

组件接口保持不变：

```ts
props: {
  entries: readonly CultureEntry[]
  sources: readonly SourceRef[]
}
```

### 要完成

- [ ] 根据 `entries` 中的 `category` 动态生成分类，提供“全部”选项。
- [ ] 切换分类时正确筛选，不把分类名或资料数量写死。
- [ ] 资料卡片显示标题、摘要、分类及传统资料／原创内容标记。
- [ ] 完善图文详情，按 `body` 段落、`images`、`sourceRefs` 展示。
- [ ] 保留关闭、返回和键盘焦点恢复。
- [ ] 区分“没有资料”和“当前分类没有结果”，提供回到全部资料的操作。
- [ ] 无图时正常展示正文；有图时复用图片失败反馈，不出现破图或布局错位。
- [ ] 完善手机排版和分类按钮，不产生横向滚动。

### 完成标准

- 从传入 props 读取数据，不修改数组、条目或全局状态。
- 用 `entry.id` 作为列表 key；来源按 sourceRefs 对应到 sources。
- 当前样例可以正常打开；多分类和空结果逻辑用本目录中的测试数据检查。
- 分类、详情关闭可用键盘操作，390px 页面不溢出。
- 只修改 culture 目录，交付修改文件及实际检查结果。

当前只有一条正式资料，不能据此声称已检查完整分类数据。需要更多正文、图片或临时浏览器验收场景时，向主开发者提出具体需求。

## 3. 队员 2：白乡故事

任务入口：[StoriesModule.vue](../app/src/modules/stories/StoriesModule.vue)。详细模块约定：[stories/README.md](../app/src/modules/stories/README.md)。

### 已经提供

- StoryEntry、SourceRef 和 PatternId 类型。
- 一条原创数字创作手记，配有本项目 Demo 导出的图片。
- 最小列表、详情、图片说明、来源组件及相关模板入口。
- 主系统处理模板选择和路由，队员只发出事件。

组件接口保持不变：

```ts
props: {
  entries: readonly StoryEntry[]
  sources: readonly SourceRef[]
}
emit: selectPattern(id: PatternId)
```

### 要完成

- [ ] 完善故事列表，显示标题、摘要、分类与内容性质。
- [ ] 完善图文详情的段落间距、图片比例和说明。
- [ ] 按 `kind` 显示“原创内容”或“传统工艺资料”，不靠标题猜测。
- [ ] 展示提供的图片说明、署名和来源；保留素材许可信息，不自行改写许可。
- [ ] 正确处理无内容、无图、多图、图片失败和无相关模板的情况。
- [ ] 相关模板按钮发出正确的 `selectPattern` 事件，保持详情关闭与跳转流程。
- [ ] 完善手机排版、详情关闭和键盘操作。

### 完成标准

- 正文从 `body` 读取，图片从 `images` 读取，不将样例内容写进组件。
- 相关入口只使用 `relatedPatternIds`；没有关联时不显示跳转按钮。
- 发出的 PatternId 只能为 `four`、`flower`、`stripe`、`free` 中提供的值，不自行添加传统纹样 ID。
- 详情关闭恢复焦点，390px 页面不溢出，图片不拉伸。
- 只修改 stories 目录，交付修改文件及实际检查结果。

当前手记是原创数字创作说明，图片是算法生成的数字作品，不能改称为传统实物、真实采访或历史记录。

## 4. 共用边界

可在各自目录新增 `.vue`、`.ts` 和必要的 `*.test.ts`，使用组件内 `<style scoped>` 与现有 CSS 变量。公共卡片不够用时，可在自己的目录组合公共组件，不直接修改 shared。

以下文件和目录只读：

- `app/package.json`、锁文件、Vite 和 TypeScript 配置。
- `app/src/app/`：公共布局、路由和全局 CSS。
- `app/src/shared/`：公共组件、类型与校验。
- `app/src/stores/`、`engine/`、`services/`：核心状态、引擎和存储。
- `app/src/content/`、公共 assets、另一个队员的目录及 demo。

数据由主系统读取后通过 props 传入。不要直接调用内容仓库、router、Pinia、Canvas 引擎或 IndexedDB。不得增加依赖、发布网站、创建新系统或把工作扩展到登录、商城、社区。

## 5. 资料与测试数据

正式内容由主开发者核对后放入 content。队员可以搜集候选资料、图片和链接，提交以下信息供核对：

| 信息 | 要写的内容 |
|---|---|
| 主题 | 拟补充的正文或图片用途 |
| 来源 | 原网页链接、标题、发布机构和查询日期 |
| 摘述 | 自己整理的简短内容，不整篇复制 |
| 图片 | 原始出处、署名、许可或明确的使用依据 |
| 问题 | 还不能确定的事实或授权信息 |

许可不清楚的图片先不进入成品。不要让 AI 编造人物、年代、采访、寓意和授权。

纯逻辑测试可使用“测试条目 A／B”“测试分类 A／B”等明确的测试数据，标为 original，不填虚构的文化事实。这些数据只放在本目录测试文件中，不接入正式页面。

组件测试工具尚未配置；可提取本目录的纯函数用现有 Vitest 检查，界面用浏览器检查。需要多条、空列表、无图或坏图的浏览器场景时，请主开发者提供临时验收数据，不在产品组件里留下测试开关。
